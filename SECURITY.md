# Безопасность сайта «Зёрна»

## Модель угроз

Проект является статическим сайтом без сервера приложений, базы данных, авторизации, форм, заказов и платежей. Поэтому в текущей версии отсутствуют серверные SQL-инъекции, захват аккаунтов и утечки из пользовательской базы. Основные риски: внедрение скриптов через DOM, подмена внешних ресурсов, небезопасные переходы на сторонние сайты, ошибки публикации и уязвимости хостинга.

## Что реализовано

- Content Security Policy в HTML: скрипты, изображения, видео и шрифты разрешены только с собственного источника; сетевые `connect`-запросы, фреймы, worker-процессы, плагины и отправка форм запрещены. Для анимаций разрешены только встроенные стили, но не встроенные скрипты. В Chromium дополнительно включён Trusted Types без разрешённых политик.
- Удалена загрузка Google Fonts и других сторонних ресурсов при открытии страницы.
- Политика `no-referrer` и `noopener noreferrer` для внешних вкладок.
- Пользовательский ввод применяется только для фильтрации текста и не вставляется через `innerHTML`.
- Нет `eval`, удалённых скриптов, аналитических счётчиков, рекламных пикселей, service worker и скрытых сетевых запросов.
- Избранное и демо-штампы хранятся только в `localStorage` с префиксом `zerna.` и могут быть удалены посетителем.
- Анимации учитывают `prefers-reduced-motion`; интерактивные элементы имеют клавиатурные состояния и доступные подписи.

## Ограничения GitHub Pages

HTML-мета CSP не заменяет HTTP-заголовки. На собственном хостинге следует настроить как минимум:

```text
Content-Security-Policy: default-src 'self'; base-uri 'self'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; worker-src 'none'; form-action 'none'; img-src 'self' data:; media-src 'self'; font-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'none'; trusted-types 'none'; require-trusted-types-for 'script'
Strict-Transport-Security: max-age=31536000
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()
Cross-Origin-Opener-Policy: same-origin
```

`includeSubDomains` для HSTS можно добавить только после проверки, что каждый поддомен всегда доступен по HTTPS.

Для коммерческого проекта с персональными данными нужно использовать инфраструктуру, соответствующую требованиям локализации РФ, вести обновления и журнал инцидентов. GitHub Pages не следует считать готовой платформой для обработки персональных данных граждан РФ.
